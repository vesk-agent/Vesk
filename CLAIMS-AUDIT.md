# Claims audit

Every claim on the home page (vesk-site `src/pages/Home.tsx`), in the docs (`docs/`) and in this README, checked against the code.

Statuses:

- **Verified**: a test exercises it. `e2e` means `pnpm test:e2e` (26 steps, the real CLI and agent against local mocks of X, PumpPortal, Jito, the RPC with a websocket, the panel and a model). `unit` means `pnpm test` (147 tests). `chart` means the site's `npm run test:chart` (19 tests). `preview` means a behaviour check in the offline preview (`tools/v11_func.py` and earlier `v*_func.py`), which drives the real UI against the mock API and sample data.
- **Implemented**: the code is there and reviewed, but nothing here can test it against the live service.
- **Fixed**: the claim was true only in part, so code was added (v7 to v11) to make it true.
- **Changed**: the wording was changed to match what the code does.

Last run (v11): e2e 26/26, unit 147/147, site tests 24/24 (crypto 5, chart 19), relay worker test ok, `tools/v11_func.py` 48/48, `tools/stability_check.py` stable at 1440 and 390, `tools/contrast.mjs` all pass. Type-checks pass for the agent, the site, the edge function and the preview.

## Notifications always leave (v18.1)

Reported: notifications popped up and never left, even after the progress bar ran out. Reproduced in the offline preview with a real pointer (`v181` scenarios in `tools/v18_1_func.py`). Root causes found:

1. **Hover stuck on.** Pausing followed React `mouseenter` / `mouseleave` on the stack. When the card under the pointer went away (× or an action button on the last card, so the stack's element unmounted; or the open list shrank under a resting pointer), no leave event ever came. Every later toast was paused, and shown expanded, until the pointer happened to cross the stack again. Reproduced: after × on the only card, the next toast stayed indefinitely with the pointer 300 px away.
2. **Two clocks.** The bar was a CSS animation and the dismissal a JS timer. On every pause the timer's remaining time shrank and was written back into the bar's `animation-duration`, which jumps a running animation ahead. The bar ran out while the toast still had seconds left (or, opened with "+N more", the bar froze while the timer ran).
3. **Pausing on a parked pointer.** A toast that appeared under a pointer that never moved counted as hovered (the browser's synthetic enter), so a cursor left near the top centre paused everything.
4. **No cap on top-ups.** A burst group or the "N more" card restarted its full time on every new line, so a steady stream kept one card up for as long as the stream ran.
5. **Exit could hang.** The stack lives outside `.app`, so the Low resource profile's no-transition rule removed the exit transition while the code still waited for `transitionend` (1.2 s fallback). Folded cards had no fallback at all.
6. **No pause for a hidden tab,** and a landed trade's 8 s / sell's 5 s didn't match the stated durations.
